# CodeAuthentic — Three targeted fixes (16 November 2026)

This package was built from `CodeAuthentic_Source_For_Review(1).zip`.

## Included changes

1. **Source-code viewer:** instructors now load a student's saved code from a **protected, on-demand** endpoint: `GET /lobbies/{lobby_id}/submissions/{submission_id}/code`. Access requires the existing JWT instructor login plus matching lobby ownership and matching submission ID. Source code is **not** included in recurring lobby lists or WebSocket messages. The response has `Cache-Control: no-store`. The modal shows loading, retry, and clipboard controls, and reports the actual **CodeBERT-tokenizer** count when available (otherwise **Unavailable**, never a fabricated zero).

2. **AI pipeline diagnostics:** classifier head files and ML dependencies can be checked without downloading models using `python -m ml.verify_pipeline --status`. Logged-in instructors can query `GET /ml/status`. Inference still uses the project's existing frozen CodeBERT 770-feature method and trained classifier heads. Missing or incompatible heads, invalid features, and invalid scores produce **failed** analyses, not simulated probabilities. The Low/Medium/High thresholds remain unchanged (40% and 70%). `python -m ml.verify_pipeline --language python --file PATH_TO_REAL_PYTHON_SAMPLE.py` exercises actual inference if weights, tokenizer and head are installed. Use `.java`/`java` and `.c`/`c` likewise.

3. **Live instructor updates:** React now subscribes to the existing `/ws/lobbies/{id}?token=...` endpoint for each instructor-owned lobby. It reacts to new and completed analyses; uses secure `wss` for HTTPS backends, reconnection with backoff, and a keepalive. The **original 10-second HTTP refresh is preserved as a fallback**, particularly useful with WebSocket-incompatible or multi-worker deployments. On logout it closes sockets and discards stale responses. Missing scores no longer display as 0.0% or green/Low by default.

## IMPORTANT: Deployment sequence

**Do not upload one file at a time to a live deployment.** Back up the current working source and any environment settings first. Deploy **backend changes and frontend changes together** (the new modal needs the new endpoint). Keep your existing `.env`, secrets, database URL, hosting variables, and any model files — these were **not** included or changed in this ZIP.

If you use the `CHANGED_FILES_ONLY` ZIP, extract it into the **project root**, preserving `backend/`, `ml/`, `src/` and `tests/` paths, and allow overwrite only for the included files. If you're unsure about paths, use the **FULL_SOURCE** ZIP instead. The full source ZIP includes the original project files plus these updates, but **not** unshared model artifacts, datasets, node_modules, or deployment secrets.

### Required model files

The supplied extracted source ZIP did **not** include these trained classifier files:

- `ml/heads/c.joblib`
- `ml/heads/java.joblib`
- `ml/heads/python.joblib`

These must be generated by the actual training process or restored from your friend's trusted trained-model backups. Do not download random `.joblib` artifacts from strangers: loading a pickle/joblib file can execute code. Install Python dependencies listed in `requirements.txt` in your friend's Python environment. The review environment had no `transformers` package; this is **not evidence** that your friend's backend is missing it.

### Quick verification on your friend's machine

```bash
# Run from the project root, inside the project's Python environment
python -m ml.verify_pipeline --status
python -m ml.verify_pipeline --language python --file path/to/real_sample.py
python -m ml.verify_pipeline --language java --file path/to/real_sample.java
python -m ml.verify_pipeline --language c --file path/to/real_sample.c

# Isolated route/model regression tests (requires pytest)
python -m pytest -q tests/test_review_fixes.py

# WebSocket client test (requires npm-installed dev dependency: typescript)
node tests/test_websocket_client.cjs

# Full frontend validation (requires dependencies installed from package-lock.json)
npm ci
npm run lint
npm run build
```

`--status` exits nonzero when dependencies or trained head files are missing. Passing it is a **prerequisite**, not proof of detector accuracy. Real inference must finish successfully for each language, and the classifier should be evaluated on held-out labelled code before claiming real-world accuracy.

### Instructor/student manual smoke test

1. Sign in as an instructor (email verification should remain absent). Create an exam lobby. Open the share link in an incognito window as a student.
2. Submit a valid C, Java or Python source file with at least 30 **CodeBERT tokens**, appropriate for that lobby. Observe a pending row, followed by a real score/risk or a clear **Failed** state.
3. Select **Inspect** and confirm that the exact original source code and its token count appear. If the tokenizer is unavailable, the code still displays and the token count reads **Unavailable**.
4. Keep the instructor dashboard open, make a second submission, and confirm it updates automatically. If the WebSocket host is not compatible, confirm updates still arrive through the 10-second polling fallback.
5. Sign in as a **different instructor** and verify that they cannot access the first instructor's submission code. Sign out and verify the protected endpoint returns 401.
